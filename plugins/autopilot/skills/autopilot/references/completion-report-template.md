# 完成报告模板

设计原则：**决策卡先行**（顶部复用验收决策卡结构，区块标题为契约字面），**信任来自证据链**，**过程细节收缩**（全表/清单按需，不顶格）。

按以下结构输出（顶部 = 验收决策卡复用，结构与空区块规约见 `references/qa-report-template.md`「验收决策卡」章节）：

```markdown
## ✅ autopilot 完成报告

**{一句话总结——消费视角：你得到什么/还欠什么}**

### 端到端真实验证结论
{1-3 行，与 state.md `e2e_status` 一致；未实证链路点名}

### 遗留问题
- {每条一行：影响面 + 建议处理时机；无则写「无」}

### 风险
- {每条一行；无则写「无」}

### 证据一行链
- {命令} ｜ {结果} ｜ exit={码}

### 提交
`{git log --oneline -1 的完整输出}`
```

过程区块（关键数字 / 变更清单 / QA 证据链全表）**不进顶格报告**——用户「要细看」时按需输出或走 tunnel 详审页（references/tunnel-review-guide.md）。

## 格式要求

- 一句话总结不超过 80 字，用户 2 秒内能判断是否需要关注
- 「证据一行链」2-4 行关键命令（取代 tree_sig 哈希与逐条命令清单）
- 「遗留问题」「风险」是信任的关键——主动暴露不完美比被发现更好；无则明确写「无」
- 遗留统一叫法「遗留问题」（禁止挂账/Follow-up/Important 等多叫法），条数与 `leftover_critical` 口径一致（用户可感知/影响核心链路的条数）
